# ブランチ分割計画

## 概要

現在の変更を単位ごとにブランチに分割する計画です。

**ルール**:

- 新規追加の対象（テスト等）は全てブランチを分ける
- 既存修正は関連する新規のPRに混ぜる（コミットは分ける）
- **コンフリクトなどが発生した時点で作業を中断し、指示を仰ぐ**

| -------- | ------------------- | --------------------------------- | -------- |

## Git ワークフロー（厳守）

各ブランチ作成時は以下のフローを厳守してください。

**注意**: コンフリクトやエラーが発生した場合は、即座に作業を中断し指示を仰ぐこと。

```bash
# 1. 全ての変更をステージに追加（新規ファイルをstashに含めるため必須）
git add .

# 2. スタッシュに保存（どの作業用かわかるメッセージ付き）
git stash push -m "wip: <ブランチ名>用の変更"

# 3. ベースブランチに切り替え & 新規ブランチ作成
git switch -f <ベースブランチ>
git switch -c <ブランチ名>

# 4. スタッシュを復元
git stash apply stash@{0}

# 5. 全てアンステージ
git unstage

# 6. コミットしたいファイルだけ追加してコミット
git add <ファイル1> <ファイル2> ...
git commit -m "<コミットメッセージ>"
```
